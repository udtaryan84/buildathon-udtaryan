## Why fork this repo?

Everyone starts from the same commit (the **genesis commit**) at the same time. Organizers can then check that:
- all code was written **during** the Buildathon and not brought in from an earlier project,
- teams commit steadily instead of pasting in one huge AI-generated dump at the end,
- every repo stays public and visible while you build.

The organizers track every fork automatically: commits, timing and activity. Read [RULES.md](RULES.md) before you write any code.

## ✅ Setup (about 5 minutes, do it at 3:00 PM)

**In short:** fork → register your fork in the form **by 3:30 PM** → build → push before 7:00 PM.

### 1. Fork this repo
Click **Fork** (top right). On the fork screen:
- **Owner:** one team member's personal account. Only **one fork per team**.
- **Repository name:** `buildathon-<team-name>`, for example `buildathon-byte-bandits`
- Click **Create fork**.

> ⚠️ Don't download a ZIP or copy the files into a new repo. **It has to be a real GitHub fork**, or the tracker can't see you.

### 2. Keep it public
Forks of a public repo are public. **Don't make it private, archive it, or delete it** until judging is over.

### 3. Add your teammates
In your fork: **Settings → Collaborators → Add people**. Add each teammate's GitHub account so their commits count toward the team.

### 4. Enable Actions
Open the **Actions** tab of your fork and click **"I understand my workflows, go ahead and enable them"**. This runs the automatic check on every push.

### 5. Make your registration commit (your first commit)
Fill in [`team.json`](team.json). `track` must be one of `physical-world`, `ai-agents` or `area-of-expertise`. Then:

```bash
git clone https://github.com/<your-username>/buildathon-<team-name>.git
cd buildathon-<team-name>
# edit team.json
git add team.json
git commit -m "register: <team name>"
git push
```

The **Hackathon check** in the Actions tab should go green ✅. If it's red, open the run to see what's wrong in `team.json`.

### 6. Register your fork (deadline: 3:30 PM IST)
👉 **[https://forms.gle/ZJUYKwTYjsMsVB2b9](https://forms.gle/ZJUYKwTYjsMsVB2b9)**

It's a 4-question Google Form: team name, fork link, track, team members. It connects your repo to the organizers' live tracker.

- Fill it in **once per team**, right after forking, and **no later than 3:30 PM IST**. **Teams that don't register can't be tracked.**
- Paste your **fork's** URL (`https://github.com/<you>/buildathon-<team-name>`), not this starter repo's.
- Need to change something? Use the **"Edit your response"** link on the confirmation page. Don't fill it in twice.
- **Final submission is automatic.** Whatever is pushed to your fork at 7:00 PM IST is what gets judged.

## Your project

# Jaisa Tha: a dashcam for your rental deposit

- **Team:** udtaryan (Aryan Salooja, @udtaryan84)
- **Track:** Build for the Physical World
- **Live app:** https://jaisa-tha-udtaryan.netlify.app

**Problem.** Tenants in Indian cities pay a large security deposit (often 2 to 10 months of rent) and lose part of it at move-out for damage that was already there or for normal wear. Most tenants do take photos, and still lose, for three reasons. The photos are not comparable (different angle and light, months apart). The landlord never saw them, so it is "that was not there" against a camera roll. And fighting costs more than giving in, because the landlord holds the money. Jaisa Tha works like a dashcam: the point is that a dated, agreed record on day one makes inflated claims not worth trying.

**What we built.** A phone web app with a three-step flow.
1. **Move-in.** Enter the deposit, then photograph each spot. The AI notes damage that is already there. Every photo gets a server timestamp and a SHA-256 fingerprint. The landlord opens one WhatsApp link and taps "I acknowledge", which records their name and the time.
2. **Move-out.** The camera shows the move-in photo faded on top so the tenant can line up roughly the same shot. It does not need to be exact.
3. **Verdict.** Every change is marked Already there (Rs 0), Normal wear (Rs 0) or Damage (cost from a fixed rate card). The ledger shows deposit held, damage found, unpaid dues and what should come back. Drag a slider to compare before and after. One tap sends a polite Hinglish WhatsApp message with the evidence link.

**The hardest part.** Comparing two photos of the same spot taken months apart in different light and framing, and judging fairly. The AI must ignore lighting, shadows and framing, treat anything in the move-in notes as already there, call doubtful cases normal wear, and never invent damage. Costs are never made up by the model: it picks a damage type and our code looks up the price. The rules that decide fairness run in code after the model answers, and 46 offline tests cover them. Long-term trust comes from the sealed record (see `docs/STORAGE.md`).

**Stack.** Vite and React, Netlify Functions and Blobs, Gemini vision models with a fallback chain.

**How to run it.** `npm install`, put `GEMINI_API_KEY=...` in `.env`, then `npx netlify dev`. Tests: `node netlify/lib/test/run.mjs`.

**Demo script (2.5 minutes).**
1. Ask who has lost money from a deposit. Show the move-in report with the landlord's acknowledgement time and the seal.
2. Move out three spots with the faded overlay: something already there, ordinary wear, and a fresh marker mark.
3. Show the verdict ledger and the claim bar, then send the WhatsApp message.

Jaisa Tha is an evidence tool, not legal advice.
